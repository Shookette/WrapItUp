# /delete-comment

Le code de Wrap It Up ne contient pas de commentaires (ADR `docs/adr/0001-adr-et-pas-de-commentaires.md`). Ce skill retrouve ceux qui restent, les classe et applique l'action prévue. Portée : `$ARGUMENTS` s'il est fourni, sinon tout le dépôt.

## 1. Inventaire

Lancer `npm run lint` : chaque diagnostic `wrap-it-up(no-comments)` est un commentaire à traiter (couvre `src/`, `tests/`, `lint/`, `vite.config.ts`). Le lint ne voit pas les autres fichiers : les parcourir aussi.

```bash
git ls-files 'src/**' 'tests/**' 'lint/**' '*.rules' vite.config.ts .github/workflows .env .env.production .gitignore \
  | grep -vE 'routeTree.gen|\.(png|svg)$' \
  | xargs grep -nE '^\s*(//|/\*|\*( |/|$)|#)|\{/\*'
```

- Ne **jamais** toucher `src/routeTree.gen.ts` (généré), `package-lock.json`, `.git-blame-ignore-revs` (chaque commit ignoré y est annoté, c'est le format du fichier).
- Ne pas compter comme commentaires : `/// <reference … />`, les directives `oxlint-disable…` / `@ts-expect-error` (mais vérifier qu'elles portent `-- #<issue>` ou `-- docs/adr/…`), un `//` dans une chaîne ou une URL.

Lire chaque commentaire **avec son code** (quelques lignes autour) avant de le classer.

## 2. Classement

| Catégorie  | Reconnaître                                                                                                                                           | Action                                 |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| Tautologie | Répète le nom, le type ou le corps (`// Create a new router instance`, JSDoc qui paraphrase une prop)                                                 | Supprimer                              |
| Obsolète   | Parle d'un code ou d'un outil disparu (Mantine, « auto-generated by… » sur un fichier modifié, règle dépassée)                                        | Supprimer                              |
| Excuse     | Justifie un contournement : « on tolère », « à garder aligné », « pas encore », « volontaire » + lint désactivé, obligation non imposée par les types | Supprimer **et** ouvrir une issue      |
| Décision   | Explique un choix non évident, ses raisons ou ses contraintes externes (sécurité, Firebase, RGPD)                                                     | Supprimer **et** consigner dans un ADR |

En cas de doute entre excuse et décision : si on voudrait que le code change un jour, c'est une excuse ; si le choix doit rester et être compris, c'est une décision. Un même commentaire peut mêler les deux : traiter chaque partie.

Avant de créer quoi que ce soit, présenter le tableau complet (fichier:ligne, extrait, catégorie, action) à l'utilisateurice.

## 3. Actions

### Excuse → issue

1. Chercher une issue existante : `gh issue list --label tech-debt --state all --search "<mots-clés>"`.
2. Sinon `gh issue create --label tech-debt --title "…" --body-file …`, en français. Corps : le commentaire supprimé (cité, avec son fichier), « ## Problème » (le contournement et son risque), « ## Piste » (la correction).
3. Si le commentaire justifiait une directive `oxlint-disable…`, garder la directive et la suffixer : `// oxlint-disable-next-line <règle> -- #<issue>`.

### Décision → ADR

1. Vérifier dans `docs/adr/README.md` qu'aucun ADR ne la couvre déjà ; sinon compléter celui-ci.
2. Nouveau fichier `docs/adr/NNNN-titre-en-kebab.md` (numéro suivant), en français :
   `# N. Titre` ; `- Statut : acceptée` ; `- Source : <fichiers d'origine>` ; `## Contexte` ; `## Décision` ; `## Conséquences`.
3. Ajouter la ligne au tableau de `docs/adr/README.md`.

### Suppression

Supprimer le commentaire et les lignes vides en trop qu'il laisse. Ne modifier aucun code au passage : la correction d'une excuse se fait dans la PR de son issue.

## 4. Vérifications et ratchet

```bash
npm run format
npm run lint:ratchet   # abaisse les tolérances de `allowed` (.oxlintrc.json), ne les augmente jamais
npm run lint && npm run test:lint && npm run test:rules && npm run build
```

- `lint:ratchet -- --accept` augmente les tolérances : uniquement pour étendre le lint à un nouveau dossier, jamais pour faire passer un nouveau commentaire.
- Mettre à jour `docs/adr/README.md`, et `CLAUDE.md` si une convention change.

## 5. Bilan

Terminer par : nombre de commentaires par catégorie, issues créées (liens), ADR créés ou complétés, lignes supprimées (`git diff --shortstat`), et tolérances restantes dans `allowed`.
